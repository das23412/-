# 发布检查清单（每次修改代码后必做）

> 背景教训：2026-08-29 的版本因为「CI 调试签名每次不同 + 版本号未变」，
> 导致用户无法覆盖安装、必须卸载旧版（丢失书架进度）。每次发版前逐条核对：

## 0. 修改前备份（强制，先于一切改动）

对仓库做任何代码/文档修改之前：

1. GitHub 上创建备份分支 `backup/<日期或版本>` 指向当前 main（`git branch backup/xxx` 并推送）；
2. 本地打源码快照 tarball；
3. 涉及密钥（`moyue-release-key`）等不可再生资产的操作，先确认副本数量、再征得确认。


## 1. 版本号必须递增（必做）

发布新版本时需要同步改三处版本号：

1. `pubspec.yaml`：以当前 pubspec 的 version 为准（三段语义版本 + 构建号，构建号每次 +1）
2. `lib/core/app_info.dart`：version 与 build 与 pubspec 保持一致（应用内“检查更新”用它对比）
3. 推送前打标签以自动发布 Release（应用内更新就查 Release）：
   ```bash
   git tag v1.6.0
   git push origin v1.6.0
   ```
   Actions 会自动构建并创建带 APK 附件的 GitHub Release。

## 2. 正式签名（2026-09-27 已轮换 ✓）

**密钥已轮换**：不再使用提交在仓库里的 debug 密钥（任何人可伪造同签名更新），
改为私密正式密钥，只存在于两处：开发者本机的 `D:\glmchunchu\moyue-release-key\`
（务必备份，丢失后所有用户永远无法覆盖安装）和仓库 Secrets（加密存储）。

- 4 个 Secrets：`MOYUE_KEYSTORE_BASE64` / `MOYUE_STORE_PASSWORD` /
  `MOYUE_KEY_ALIAS`（= `moyue-release`）/ `MOYUE_KEY_PASSWORD`；
  CI 构建时注入 `android/key.properties`，Gradle 用 PKCS12 密钥库签名
- 未配置 Secrets 时 CI 会**直接失败**（拒绝产出随机签名包），这是故意的
- 密钥库为 PKCS12 格式，`build.gradle.kts` 已设置 `storeType = "pkcs12"`
- 密钥密码同时是 store 与 key 的密码（PKCS12）

**一次性迁移成本**：v1.6.0 起签名与旧版不同，从 1.5.0 及更早版本升级需要
**卸载重装一次**（书架/进度会清空）；1.6.0 之后的所有版本恢复覆盖安装。
发 Release 时公告里必须写明这一点。

## 3. 发布流程

1. 改完代码 → `flutter analyze` + `flutter test` 本地过一遍；
2. 提交并推送（等 GitHub 连接窗口，重试 `git push`）；
3. 等 Actions 构建变绿；
4. 把最新一次 run 的 Artifacts → `moyue-apk` 链接发给用户；
5. 发版时在 Release 说明里写清升级方式（1.5.x → 1.6.0 需卸载重装）。
