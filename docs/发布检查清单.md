# 发布检查清单（每次修改代码后必做）

> 背景教训：2026-08-29 的版本因为「CI 调试签名每次不同 + 版本号未变」，
> 导致用户无法覆盖安装、必须卸载旧版（丢失书架进度）。每次发版前逐条核对：

## 1. 版本号必须递增（必做）

编辑 `pubspec.yaml`：

```yaml
version: 1.1.0+2   # 三段语义版本 + 构建号，构建号每次 +1，不许重复
```

## 2. 固定签名（一次性配置，之后自动生效）

当前 CI 使用 runner 自动生成的调试密钥，**每次构建都不同**，会导致覆盖安装失败。
需改为固定密钥：

1. 生成密钥库（`keytool`，有效期 100 年）；
2. 在 GitHub 仓库 → Settings → Secrets and variables → Actions 添加 4 个 Secret：
   - `MOYUE_KEYSTORE_BASE64`（密钥库文件的 Base64）
   - `MOYUE_STORE_PASSWORD`
   - `MOYUE_KEY_ALIAS`
   - `MOYUE_KEY_PASSWORD`
3. 工作流 `.github/workflows/build.yml` 已内置读取这些 Secrets 的步骤，
   配好后所有构建自动使用同一把签名。

> 在 Secrets 配置完成之前，每个新版本首次安装仍然需要先卸载旧版（会丢书架进度），
> 提醒用户提前截图/记录正在读的书目。

## 3. 发布流程

1. 改完代码 → `flutter analyze` + `flutter test` 本地过一遍；
2. 提交并推送（等 GitHub 连接窗口，重试 `git push`）；
3. 等 Actions 构建变绿；
4. 把最新一次 run 的 Artifacts → `moyue-apk` 链接发给用户；
5. 提醒覆盖安装即可（签名固定后不再需要卸载）。
